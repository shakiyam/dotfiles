# Rollout Commit

引数: $ARGUMENTS

1. このファイルと同じディレクトリにある `precheck.sh <リファレンス> <コミット>` を実行する。失敗したら理由を伝えて止まる。出力の形式はスクリプト冒頭のコメントを参照する。
2. `candidate`（ファイルを追加するだけのコミット）がある場合は、展開先をユーザーに確認して止まる。
3. `apply` のリポジトリで、`apply=` のパスのうちリファレンスで変更・追加されたものを `git -C <リファレンス> show <コミット>:<パス>` の内容で上書きし、modeをリファレンスに合わせる。削除されたものには触れず、手順6に回す。
4. 各リポジトリで、変更したファイルの種類に対応するlintのMakeターゲットと、変更したファイルを使うMakeターゲットを実行する。レシピが既存の問題で途中で止まった場合は、残りの行を個別に実行して確認する。失敗は今回の変更が原因か既存の問題かを区別し、今回の変更が原因のリポジトリは以降の手順から外し、変更は残したまま報告して、元に戻す `!` コマンドを提示する。
5. 変更・追加したファイルだけを `git add` する。
6. リポジトリごとの結果を表で報告する。`exception` は理由を示し、`differs` はリファレンスとの差分をcompare-repoスキルの(a)/(b)/(c)で分類する。`other-changes` は同時進行の変更として明記する。続けて、次の `!` コマンドをbashの構文で1行ずつ提示し、ユーザーの実行を待つ。
   - 削除されたファイルがある場合: `git -C <リポジトリ> rm -q <パス…>`
   - コミット: `git -C <リポジトリ> commit -m '<リファレンスのコミットの件名>' -- <パス…>`。件名に含まれる `'` は `'\''` にエスケープし、パスには削除されたものも含める
7. コミット後、各リポジトリがupstreamより先行しているだけであることを `git rev-list --left-right --count @{u}...HEAD` で確認し、`git -C <リポジトリ> push` の `!` コマンドを1行で提示する。
