# Orchestrate Repos

引数: $ARGUMENTS

1. 前提を確かめる。`HERDR_ENV=1` であること、引数のリポジトリがすべて存在することを確認し、満たさなければ理由を伝えて止まる。herdrスキルで同梱の手順書を読み込む。
2. 各セッションに送る指示文と対象のリポジトリをユーザーに示し、承認を待つ。事前に決まった変更を配る場合は、コミットの件名も示す。件名は、手本となるコミットがあればその件名とし、手本が1つに決まらないかない場合はここで案を示す。作業を引き継ぐ場合は、件名を示さず、引き継ぎ書を書いてそのパスを指示文に入れる。件名は、引き継いだセッションがユーザーと決める。指示文には次を必ず入れる。
   - 結果はSendMessageで送信元に返信し、最後の行を `=== END ===` にすること。引き継ぎの場合は、引き継いだ作業をすべて終えたときに返信すること
   - 普段のワークフローに従い、コミット案の提示まで進んだら止まること。ユーザーがコミットしたら、pushの `!` コマンドを提示すること
   - 変更を配る場合は、コミットの件名。手本のコミットがあれば、`git -C <手本のリポジトリ> show <ハッシュ>` で中身を確かめられるようにする。件名はそのまま使い、リポジトリの事情で合わない場合は理由を添えて別の案を返すこと
3. リポジトリごとに、`herdr agent list` で、そのリポジトリを `cwd` にするClaudeのエージェントがいるかを確かめ、指示を送るセッションを決める。
   - いる場合: それを使う。宛先は、ListAgentsでリポジトリのディレクトリ名を含む名前のセッションを探して決める。宛先が決められない場合(該当する名前がないか、複数ある場合)は、新しく作らずにユーザーに確かめる。
   - いない場合: `herdr workspace create --cwd <リポジトリ> --label <リポジトリ名> --no-focus` を実行し、返されたタブを `herdr tab rename <タブID> claude` で改名し、返されたルート・ペインで `herdr agent start <名前> --kind claude --pane <ペインID> -- --name <名前>` を実行する。名前は、同梱の手順書の命名規則に合うようにリポジトリ名から作り、そのまま宛先になる。`agent_not_ready` が返ったら `herdr agent read` で状況を確かめ、フォルダの信頼確認などはどのワークスペースのものかを示してユーザーに渡す。続けて、`hunk session list` にそのリポジトリのセッションがなければ、同じワークスペースに `herdr tab create --workspace <ワークスペースID> --cwd <リポジトリ> --label hunk --no-focus` でタブを作り、返されたルート・ペインで `herdr pane run <ペインID> 'hunk diff HEAD --watch'` を実行する。シェルだけのタブは、Hunkのセッションの有無にかかわらず、`--label shell` で同じように作る。
4. 手順3で決めた宛先に、SendMessageに `notify_when_idle: true` を付けて指示を送る。
5. 各セッションが手順2の指示に従ってSendMessageで返す結果を待ち、最後の行が `=== END ===` のものを完了とみなす。ポーリングはしない。返信がないままidle通知が届いたら、`herdr agent read` でそのペインの状況を確かめる。承認待ちやセッションからの質問は、どのワークスペースのものかを示してユーザーに渡す。
6. 結果をリポジトリごとの表にまとめて報告する。手順2で件名を示した場合、類似の変更でセッションごとに件名の案が違うときや、件名を手順2から変えるときは、件名を1つに揃え、まだコミットしていないすべてのセッションにSendMessageで伝えて提案し直させる。コミットとpushは各ワークスペースでユーザーが行う。
7. ユーザーが各ワークスペースでpushまで終えたら、各リポジトリでステージした変更が残っていないこと(`git -C <リポジトリ> diff --cached --quiet`)と、upstreamより先行するコミットがないこと(`git -C <リポジトリ> rev-list --count @{u}..HEAD` が0)を確かめる。満たさないリポジトリは、どのワークスペースかを示してユーザーに伝える。そのうえでユーザーの確認を取ってから、手順3で作ったワークスペースを `herdr workspace close` で片付ける。既存のセッションのワークスペースは閉じない。
